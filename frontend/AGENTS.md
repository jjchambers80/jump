# Frontend — Scoped Agent Instructions

Loads when agent touches `frontend/` files. For root-level commands and env vars, see [`../AGENTS.md`](../AGENTS.md).

## Routing Structure

```
app/
├── admin/           # Organizer/admin dashboard (session-protected)
├── events/          # Public event browsing + detail pages; [eventId]/apply/* application forms + status page (spec 011)
├── auth/            # Sign-in page
├── checkout/        # Cart + payment flow
├── confirmation/    # Post-purchase confirmation
├── orders/          # [orderId] detail (buyer session or staff) + lookup
├── venues/          # Venue pages
├── organizations/   # Public org page + [orgId]/account (buyer sign-in, orders, tickets, applications, applicant business profile)
├── api/auth/        # Auth.js API route handler (staff)
└── api/buyer/       # Buyer session proxies: request/verify/logout/me/* (httpOnly jump_buyer cookie); me/applications*, me/applicant-profile[/photos] forward JSON — the photos route forwards multipart
```

## Key Files

- `auth.ts` — Auth.js v5 config (Google OAuth, magic link, `password` / `token-bridge` Credentials, dev-only `dev-email`; JWT strategy, Prisma adapter). `auth.config.ts` is the edge-safe subset (providers, `trustHost`, HS256 cookie codec from `lib/authJwt.ts`) that `src/middleware.ts` also uses
- `services/api.ts` — All backend API calls go through here
- `lib/addOns.ts` — Add-on types and helpers (spec 012): `offeredAddOns` (which add-ons a cart's tiers offer), `addOnAllInPrice`, `parseAddOnLines`. `components/AddOnPicker.tsx` renders the steppers; the event page carries lines to checkout as `?addOns=[{addOnId,quantity}]`. Admin section: `app/admin/events/[eventId]/edit/AddOnsSection.tsx` (saves through the API immediately, outside the event form). Applications (phase 2, moved by spec 037 phase 5): `ChooseSpace` renders `AddOnPicker` for the vendor's category (`selection.addOns`, per-unit `applicantPays` from the API, total line is an estimate — the server allocates fees across lines) and sends `addOns` with `POST …/select`; the apply form carries none; admin detail shows lines + `EditAddOnsDialog` (gated by `addOnsEditable`), the list has an `addOn` filter (saved views carry it) and column, the form editor's tier edit row sets "Add-ons offered" via `setTierAddOns`. Analytics page (`admin/events/[eventId]/analytics`) shows the add-on sales table + purchasers CSV (`AddOnSales` type); its amounts are dollars, never divide by 100
- `lib/applications.ts` — Shared types, labels and helpers for spec 011; admin calls live in `app/admin/events/[eventId]/applications/useApplicationsApi.ts` (also `useTemplatesApi` for Settings › Applications). Admin list saved views are `localStorage` (`jump.applications.views.<eventId>`), never server state
- `components/` — Shared React components
- `lib/` — Utilities and helpers (`lib/color.ts` — WCAG contrast + brand CSS vars; `lib/fees.ts` — all-in fee math mirroring backend `FeeService`; `lib/buyerSession.ts` — server-only buyer cookie + backend proxy, signs the client IP for the backend rate limiter)

## Patterns

- **Server vs Client**: Default to server components. Add `'use client'` only when needed for interactivity
- **Data fetching**: Server components fetch directly; client components call `services/api.ts`
- **Admin pages**: `src/middleware.ts` redirects unauthenticated `/admin*` to `/auth/signin?callbackUrl=…` on the edge; pages keep `AdminRoute`/`ProtectedRoute` as the second layer. Add new admin pages to the sidebar navigation
- **Search params**: Always wrap `useSearchParams()` consumers in `<Suspense fallback={...}>`
- **Tenant hosts**: `src/middleware.ts` rewrites requests on an organization's custom domain (`/` → org page, `/account` → buyer account, admin/auth → 404) using `lib/storefrontHost.ts`. Pages receive the same `params.orgId` as on the platform host, so no page needs host awareness. Platform hosts come from `NEXT_PUBLIC_PLATFORM_HOSTS` / `AUTH_URL`. `/legal/*` passes through on every host (Jump's own text, spec 023): keep it in `PUBLIC_PASS`
- **Legal pages (spec 023 phase 0)**: `app/legal/[slug]/page.tsx` renders `content/legal/<slug>.md` (`lib/legalContent.ts`, `marked`) only when `NEXT_PUBLIC_LEGAL_PAGES_ENABLED`; never commit placeholder text there — the route ships dark until counsel's documents land. Link legal paths through `LEGAL_PATHS` / `LEGAL_PAGES_ENABLED` in `lib/legal.ts`, never hard-code `/terms`
- **Buyer auth**: never call `/buyer/*` on the backend from the browser and never use Auth.js for buyers. Go through `app/api/buyer/*` route handlers so the session stays in the httpOnly cookie. There is no `/my-tickets`; buyers self-serve on `/organizations/[orgId]/account`. See `docs/wiki/features/buyer-accounts.md`
- **Signup / onboarding (spec 022)**: `app/signup/*` lives outside `/admin` (no `OrgProvider`; `SignupGuard` = `ProtectedRoute` with `callbackUrl`). The switcher's **Create organization** opens `/signup?from_admin=1` in a new tab; `lib/orgChannel.ts` (`BroadcastChannel('jump-org')`) tells the opener's `OrgProvider` to refetch and select the new org, and `/admin/dashboard?org=<id>` does the same on first load. `AdminRoute` sends `UNASSIGNED` users to `/signup`. The done page calls `useSession().update()` — `auth.ts` refreshes claims on `trigger === 'update'`; keep that branch. Survey option ids in `lib/onboarding.ts` mirror `backend/src/config/onboarding.js` (contract test). The dashboard `SetupGuide` reads `GET /admin/setup-guide`; copy lives in the component. Billing (phase 2): `components/billing/EmbeddedCheckout.tsx` mounts Stripe embedded Checkout with `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` (Jump's account) for the subscribe step and Settings › Plan (`app/admin/settings/plan`, `usePlanApi`); Stripe returns to `…/subscribe/return?session_id=` / `/admin/settings/plan?session_id=`, which POST `confirm`. The Plan nav entry is gated by `NEXT_PUBLIC_BILLING_ENABLED` (build-time). See `docs/wiki/features/organization-onboarding.md`
- **Org switcher**: `OrgContext` publishes the selection with `setActiveOrganizationId` *synchronously inside its setter* (child effects run before provider effects — never move this into a `useEffect`); `services/api.ts` sends it as `X-Jump-Org`. Org-scoped pages fetch only after `useOrg().loading` is false and refetch on `selectedOrgId` change, not on `loading` toggles (`refresh()` flips it). See `docs/wiki/features/org-switcher.md`
- **Brand colors**: On public organization/venue/event pages and `EventCard`, use the `brand` tokens (`bg-brand`, `hover:bg-brand-hover`, `text-brand-fg`, `text-brand-link`) instead of raw `blue-600`/`indigo-400` classes. Wrap the page root in `<BrandScope color={…} themeMode={…}>`. Color math lives in `lib/color.ts`; see `docs/wiki/features/organization-branding.md`
- **Settings editors**: Settings › General is read-only summary rows (`app/admin/settings/SummaryRow.tsx`) that open modals built on `app/admin/settings/SettingsDialog.tsx` (focus trap, Escape/backdrop, discard confirm, Cancel/Save header). New settings sections should reuse both rather than inline forms; each dialog PATCHes only its own fields. See `docs/wiki/features/organization-settings.md`. Settings › Tax (`app/admin/settings/tax/`) follows the Domains pattern: a `useTaxApi` hook that appends `?organizationId=` for SYSTEM_ADMIN, table rows as buttons with per-row refs for focus return, and a plain confirm dialog (not `SettingsDialog`) for the tax-inclusive switch — see `docs/wiki/features/tax-settings.md`. Settings › Payments (`app/admin/settings/payments/`) follows the Tax pattern (`usePaymentsApi`, `SettingsDialog` for the statement name, per-row `role="switch"` toggles with optimistic rollback on the methods sub-page) — see `docs/wiki/features/payments-settings.md`
- **Themed storefront (spec 038)**: the org home, Content pages and blog routes first call `loadStorefrontFrame` (`theme/server/storefront.ts`); on `theme` they render on the server through `ThemedStorefront` / `ThemedContentPage` (`ThemeFrame` = `ThemeScope` + header/footer documents via Puck `Render` from `@puckeditor/core/rsc` + the page body). The org home (`/`) and `/organizations/[orgId]/events` (tenant `/events`) render the theme's template document; the `EventsHero` / `EventList` sections reuse `EventsCover` / `EventsListing`, which the legacy `OrganizationEventsBody` also renders, so the default theme matches today's page pixel for pixel (parity spec in `e2e/storefront-themed.spec.ts`). Content pages and blog keep fixed bodies (`StorefrontPageBody`, `BlogListingBody`, `BlogPostBody`) until 038G, otherwise they render the legacy client views unchanged. Keep bodies server-safe (no hooks) so both paths share them. Store access on themed pages is the httpOnly `jump_store_access_<orgId>` cookie from `app/api/storefront/access/[orgId]` (POST unlock, DELETE expire); the server forwards every such cookie. Playwright serves the Next server's fetches from `e2e/fixtures/server.mjs` (canned data per org id in `e2e/fixtures/storefront.mjs`). Contracts: `specs/038-theme-editor/contracts.md`
- **Public org storefront**: `app/organizations/[orgId]/page.tsx` is a *server* component that only exports `generateMetadata` (title/description/Open Graph from `GET /organizations/:id/public/meta`, 2 s timeout, falls back to defaults) and renders the client `OrganizationStorefront.tsx`. Keep new storefront logic in the client file. A private store (Online store › Preferences) returns `locked: true` from `/public` and 403 `details.locked` from event/venue/checkout/apply routes; `components/StorefrontPasswordGate.tsx` exchanges the password for a token kept in `localStorage` (`lib/storefrontAccess.ts`); `services/api.ts` sends every stored token as `X-Storefront-Access`. Storefront pages check `storefrontLockFrom(err)` before their generic error branch and render the gate. The event list renders `components/storefront/EventStub.tsx` (ticket stubs grouped by month in the venue zone, `.event-stub` notch mask in `globals.css`, date parts from `lib/dateTile.ts`, shared with `RsvpPass`); the venue page keeps the grid `EventCard` (`docs/wiki/features/organization-storefront.md`). See `docs/wiki/features/online-store-preferences.md`
- **Finance section**: `app/admin/finance/` — landing (links to Payouts, Settings › Tax, Settings › Payments) and `finance/payouts` (live balance + payout history from `GET /admin/finance/payouts` via `usePaymentsApi().financePayouts`). The bank account is connected only on `app/admin/settings/payments/payout-bank-account/` (empty state → Stripe onboarding, then `•••• last4` + `Change bank` → Express dashboard); Finance › Payouts links there and never onboards itself. Old `/admin/settings/payments/payouts` 308s in `next.config.mjs`. Bank numbers never enter Jump — see `docs/wiki/features/connect-payouts.md`
- **Content section (spec 025+)**: `app/admin/content/*` — Files, then Menus (027) and Blog posts (026) as nested sidebar items. Shared primitives live in `components/content/` (`ConfirmDialog`, `Toast` via `showToast` + one `ToastHost` per page, `CopyLinkButton`, `FileThumb`, `FocalPointPicker`, upload dialogs) and `lib/content.ts` (types + limits mirrored from `backend/src/utils/fileLimits.js`). API hooks follow the Tax pattern (`files/useFilesApi.ts`). Edit pages never autosave: a sticky save bar appears when dirty, with a `beforeunload` guard. `api.upload` sends `X-Jump-Org` like `api.request`. Blog posts (026): `blog-posts/useBlogApi.ts`, `BlogPostForm` (draft vs saved snapshot → `SaveBar`, `useUnsavedChanges` guard on ‹ › / back), `SeoListingCard` shared with Pages, `RichTextEditorField` (Tiptap, dynamic import, HTML in/out; backend sanitises), `FilePickerDialog` for featured / inline images. Storefront content pages are client views (`components/storefront/*View.tsx`) inside `StorefrontShell` (gate + brand + header) with a thin server `page.tsx` for `generateMetadata` (`lib/storefrontMeta.ts`); stored HTML renders only through `ContentHtml`. Menus (027): `menus/MenuEditor.tsx` holds the tree locally (`dnd-kit-sortable-tree`, depth rules via `canHaveChildren`) and saves it whole; `LinkPicker` is a grouped combobox over `GET /admin/menus/link-targets`. Storefront: `useStorefrontMenus(orgId)` (module cache), `OrganizationHeader nav` renders `StorefrontNav` (mobile + desktop variants), `StorefrontFooter` at the page bottom; both use `storefrontHref` for tenant short paths
- **Apply pages**: `app/events/[eventId]/apply/ApplyShell.tsx` frames the index, form and status pages with the event page's dark hero (blurred poster, `dateTile`, venue block). The form is numbered `Step` cards plus a sticky `aside` "Application summary" (cost to apply, what happens next, the submit button). Spec 037 phase 5 (apply-then-choose): the form never shows tiers, booths, add-ons, totals or a Stripe step — every form submits straight to the status page. An approved PAID vendor chooses their space on the status page and in the buyer account through `components/applications/ChooseSpace.tsx`: extras, how to pay, the held state with its countdown, and what the form sells (`selection.mode`, spec 039). **MAP**: an ARIA **Map | Spots** tablist over `BoothPicker` and `SpotList`. Spots can carry their own all-in `price`; other categories are faded and locked; `map.pending` shows a waiting state. **TIERS**: the approved category card, or, when `selection.categories` is set (the vendor picks), a radio group of space types whose extras follow the pick; both callers hand in a `SpaceApi` (`select` / `pay` / `release`) — guest routes with `?token=`, buyer ones through `app/api/buyer/me/applications/[id]/{select,release,pay}`. `needsSpaceChoice(app)` (`lib/applications.ts`) decides when it mounts; never gate on `tier.mapBound`. Storefront colours stay on brand tokens; motion is a `motion-safe` spinner only. See `docs/wiki/features/applications.md` › Apply-then-choose
- **Public org header**: `components/OrganizationHeader.tsx` (logo `LogoBox` + name, optional `nav` main menu) opens every public storefront page — org page (`as="h1"`, `nav`), event (`nav`), pages / blog (`nav` via `StorefrontShell`), apply, checkout, confirmation (no nav; links to the org page). Event payloads carry `organizationLogoUrl`. Never hand-roll a second logo `<img>`. See `docs/wiki/features/organization-logo-box.md`
- **Checkout flow**: the next action is always on screen — `checkout/[eventId]` puts the form beside a sticky summary from `lg` and pins a second submit button (`form="checkout-form"`) in a fixed bottom bar below it; the event page shows a mobile "Get tickets" bar before the cart has anything. The cart and contact details survive Stripe's `?status=cancelled` return through `lib/checkoutDraft.ts` (`sessionStorage`, guarded). Storefront sheets/modals use `lib/useDialog.ts` + `role="dialog"`. Keep `transition-colors` off themed inputs (they animate from white when `BrandScope` forces dark). See `docs/wiki/features/checkout-conversion-ux.md`
- **Fees in the cart**: All customer-facing fee math imports from `lib/fees.ts` (`computeOrderFees` for carts/orders, `computeTierAllInPrice` for a single tier card; pass `event.taxInclusivePricing` as the third argument so tax-inclusive orgs price correctly). Never copy `FEE_CONFIG` into a page. Cart lines render through `components/CartLineItem.tsx` (price = dotted-underline disclosure + breakdown accordion; down caret rendered only while open, never a closed-state caret) with `components/ExpandCollapseAll.tsx` on the heading row; open state lives in the page and is shared by desktop + mobile views. See `docs/wiki/features/cart-line-item-breakdown.md`
- **Map builder**: `app/admin/maps/[mapId]` = `components/maps/builder/*` (palette, `EditorCanvas` with its own viewport, `InspectorPanel`, dialogs) over `useMapEditor` (`commit` / `checkpoint` undo, ref-based autosave). Geometry lives in `builder/placement.ts` (Vitest); `Booth` / `MapElement` stay shared with the public map, so keep their props backwards compatible. Spec 039: the inspector's **Spot price** (`PriceField`, bulk `MultiPriceField`; rules in `builder/pricing.ts`) sets `Booth.price`. Empty means the tier's price. Autosave always sends `price`. The field is disabled on HELD / SOLD / RESERVED spots, and a 409 `BOOTH_PRICE_LOCKED` reloads the map. `Booth`'s `priceBadge` marks priced spots in the builder only. See `docs/wiki/features/map-builder.md`
- **Event editor**: `/admin/events/new` and the section editors `/admin/events/[eventId]/edit/{details,sales}` (one `edit/EventEditor.tsx` with a `scope`; `/edit` redirects by hash — spec 037 phase 3) share `components/events/EventFormLayout.tsx`; the edit page adds `EventEditSummary` (stub + capacity meter + section links) and the bottom-pinned `EventSaveCard` with a dirty snapshot and `beforeunload` guard. New sections go in the page's `sections` list (step number + jump link). Never reach a section with a plain `#anchor` or `scrollIntoView` in admin: the frame is `h-screen overflow-hidden` and both scroll it too — scroll `<main>` (`jumpTo`). Small edits from the Details page use `components/Flyout.tsx` flyouts (`components/events/EventFlyouts.tsx`); reuse `Flyout` for any new in-place section editor. See `docs/wiki/features/event-editor.md`
- **Icons**: `lucide-react` (ISC, tree-shaken per import) is the icon library — `import { Ticket } from 'lucide-react'`, `aria-hidden` when decorative. Prefer it over new hand-drawn `<svg>` paths; the inline SVGs already in `Navbar`, `admin/settings/icons.tsx`, etc. can migrate opportunistically. Empty cart state = `components/EmptyCart.tsx` (`Tickets` icon), used by the desktop Order Summary card and the mobile cart drawer
- **Org theme mode**: `BrandScope`'s `themeMode` prop forces light/dark/system on public org pages through `useThemeMode().setForced` → next-themes `forcedTheme`. Never call `setTheme` to force — it overwrites `localStorage.theme`. Types/options in `lib/theme.ts`; see `docs/wiki/features/organization-theme-mode.md`
